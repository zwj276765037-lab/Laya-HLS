# Laya推理软硬件职责重划草案

2026-10-17；A001；状态：讨论草案，未替换已批准Goal v4或启动实施。用户提出“需要重新规定整个推理架构的硬件部分具体执行什么，硬件并不是什么都擅长执行”。本轮仅整理架构与静态算式；工程、研究实验及重工具继续暂停。没有新性能实测、数值验收或物理结果。

## 建议修改的目标边界

建议把“CPU只做Embedding与调用，之后全部FPGA执行”改为：**完整模型由CPU与FPGA协同执行，FPGA承担能证明端到端收益的连续计算子图；每个算子的实际执行端明确记录，完整系统按同输入、同输出口径验收。**

模型、权重、28 Encoder＋2 Decision＋scorer/ACT、真实输入和18项最终logits保持。完整计算不能省略；软件执行明确报告为软件执行。单请求延迟、连续请求吞吐、资源和开发成本共同参与取舍。用户尚未指定新硬门槛，50ms不自动成为验收要求。

本草案不自行放宽现有数值规则。逐位一致、可接受误差、模型任务质量是不同维度；若另选FMA、不同归约或近似函数，须另定义容差和验证集。CPU实现也不能默认用任意BLAS替换现有严格参考并称逐位等价。

## 推荐职责与保留问题

| 工作 | 建议位置 | 原因与边界 |
| --- | --- | --- |
| 分词、输入检查/打包、token embedding、模型文件解析、权重准备、请求管理、错误解释和结果接口 | CPU | 现有CPU职责扩展到软件管理，避免在FPGA重建文件解析与通用业务框架。硬件仍保留地址边界、流控和真实完成/错误保护。 |
| scorer/ACT尾部：marker gather/LN、两层scorer、bias/GELU、candidate mask/softmax/log/统计、ACT拼接与FC1/FC2 | CPU优先候选 | 数据和矩阵规模小、算子种类多，能减少硬件特殊路径。仍执行原16槽及mask，不因只有两个有效候选而裁剪。尾部两次Q8共16,777,728 MAC，仅占全图Q8约0.0356%；实际CPU尾部延迟仍未知。 |
| Encoder/Decision的大矩阵QKV、WO、Wi/Down或FC1/FC2 | FPGA核心候选 | 规则、复用强、有大量独立输出；按完整矩阵或连续子图调用，不按group/小tile经Host调用。不能沿用串行供数作为既定吞吐结构。 |
| Q8分组整数点积、scale恢复、组间累加、bias及结果布局 | 与矩阵一起在FPGA | 硬件交付完整输出，CPU不逐组接收dot再恢复。全图仅传I32分组dot已需约5.895GB/请求，尚未计scale与其他数据；这是静态负担示例，非实际传输。 |
| 激活量化、残差加、ReLU、RoPE/布局转换 | 数据已驻留FPGA时优先融合；CPU边界处可另比较 | 规则、可流式；收益常来自少搬一次大张量。量化仍有amax/除法/舍入成本，不因归为辅助算子而当作免费。RoPE需计原sin/cos来源与读取。 |
| LN | 待比较CPU与硬件 | 分为规则归约/流式部分及每行少量sqrt/倒数；复杂浮点并不证明CPU更快。重点比较并行行归约、参数计算、CPU往返及上下游驻留。 |
| GEGLU/GELU | 待比较融合硬件与CPU | 位于Wi和Down之间，CPU执行会把宽中间张量送出再送回。精确tanh资源代价与近似方案分开评估，不能为了省硬件忽略传输。 |
| Attention的QK、softmax、AV | 整个子图作为分工候选 | QK/AV是矩阵计算；softmax有exp/归约，三者适性不同。首轮比较整个Attention在CPU与整个子图在FPGA，避免默认每head/每row单独跨Host传score/prob。更细切分需要实际收益依据。 |
| 地址/valid/ready、DMA、在途计数、局部完成及数据错误保护 | FPGA必要职责 | 无论分工怎样都需要可靠的数据移动。普通输入合法性、模型解析和复杂业务恢复尽量归CPU；不能删硬件保护换取表面性能。 |

以上是架构候选，不能据“CPU擅长浮点”直接断定LN、Attention或GELU应全放CPU。高频、规则浮点也可能适合FPGA；低频、小规模且分支多的工作优先CPU。

## 两个必须比较的分工边界

**候选A：大矩阵加速器。** CPU执行全部非矩阵主线与尾部；FPGA执行主线120个完整Q8矩阵（包括量化/恢复/累加/bias）。这提供职责清楚的对照方案，尚不能称为最终低延迟架构。其CPU算子可能成为主瓶颈，逐矩阵Host依赖也可能抵消收益。

**候选B：Attention在CPU，其余主线在FPGA，尾部回CPU。** FPGA保持hidden、skip及FFN中间数据驻留，执行QKV/RoPE、WO/残差和LN/FFN；每block向CPU提供Q/K/V，收回完整Attention输出。它减少往返，但依赖LN与GEGLU硬件在数值、面积、时序方面可行，不能在当前就冻结为推荐实现。

若CPU Attention本身超过系统预算，候选B应淘汰或将整个Attention并入设备；如果CPU所有非矩阵加上搬运仍可达到目标，候选A可以优先以较小工程成本交付。最终位置取决于完整关键路径，不由算子名称决定。

## 搬运预算：仅为静态情景

依[现有完整图形状](../../source/fixed_graph_architecture_20261014.md)计算；详细算式见[机读情景](hardware_partition_scenarios_20261017.json)。权重假设预先在设备内存，加载另算；激活F32，无复用/压缩跨矩阵边界。带宽与重叠未实测。

| 情景 | 主线Host↔设备激活流量/请求 | 范围 |
| --- | ---: | --- |
| 候选A，CPU发送各矩阵F32输入、取回F32输出 | 247,070,720B＝235.625MiB | 28 Encoder＋2 Decision，120个矩阵依赖交接；不是断言120次独立运行时API调用。 |
| 候选B，只交换每block的QKV和Attention输出 | 62,914,560B＝60MiB | 不含最初输入、最终尾部输入、mask/控制及CPU执行；其他主线必须驻留设备。 |

若仅作假设取聚合有效8GB/s，候选A的这些激活传输就约30.9ms，未计任何计算、同步、布局/拷贝或权重读取。该数字不是PCIe实测、完整延迟或普适下界；双向重叠需要独立建模。CPU端量化后传Q8可降低输入流量，但增加CPU量化工作并改变边界，须作为另一情景计算。

## 新设计应交付什么再进入实现

1. 对每个实际算子标CPU/FPGA、数值口径、输入输出位置和同步边界；CPU执行仍属于完整推理。
2. 用相同B/S与输入测CPU子图、设备子图和传输，列关键路径/共享资源占用；端到端包含Host工作，不只报告kernel时间。
3. FPGA核心列持续吞吐、FP恢复吞吐、片上端口、缓存及外存带宽需求；从需求选并行规模，不先锁旧阵列和“零新增缓存”。
4. 数值结果顺序与执行发射顺序分开：可交错独立输出；有界预取/在途窗口和按序提交的错误合同明确后才实现，不沿用零后继读取来限制所有候选。
5. 先验证代表性完整子图的正确性、实际周期、资源/时序与系统收益；收益不足则改变分工或结束候选，不先补齐整模硬件后再判断价值。
