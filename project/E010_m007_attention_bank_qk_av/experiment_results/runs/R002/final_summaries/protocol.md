# SM011 R002 execution protocol and evidence boundaries

Authority is `mission/M007_完整Attention高性能主干与部署闭合/tasks/SM011.md`, SOFTMAX-02. Actual implementation is this module's `rtl/` and `tb/`; raw attempts are E010/experiment_results/runs/R002/attempts. R001 remains frozen.

`tb/m011_softmax_run.py` prepares a fresh stable AT, freezes every actual RTL/V/data/reference/TB/runner/guard dependency and SHA, and rejects mutation of an existing AT. Build and RTL use the same frozen closure. Each real compiler/simulator/reference process and descendants retain the project `m007_heavy.lock`, CPU0–3/nice19/idle I/O, memory floor and RSS/wall/semantic-stall guards. Current per-attempt default is120s. A later working-source edit does not migrate an older result; current sources are checked against the particular accepted manifests.

Original Q/K/V, mask and full score/prob/out are the same enc0/head0/request3 fixture frozen in R001. AT005 uses the original full_reference.py/libm to generate local full/sliding score/max/shift/EXP/all seven adjacent sums/total/prob/context, proving normal full saved outputs equal the original fixture. AT016 derives independent full/sliding AV products and key-order partials from those original-reference probabilities and V, checking the final context. Old R001 QK products/tree/scale remain read-only expectations, hash-bound in each head attempt. No DUT numeric routine generates expectations and no whole-model gold is regenerated.

For a fresh working-source attempt, invoke `python3 tb/m011_softmax_run.py build CONFIG ATxxx_description` then `... rtl CONFIG ATxxx_description`. CONFIG is `softmax`, `head`, `fault`, `fault_order`, `reset`, or `head_control` for the current integration scope. `head --sliding` uses the independent sliding oracle. `head_control --mode abort` and `--mode reset` select their distinct legal control paths; each path gets a fresh AT. Keep the runner/source unchanged between build and its paired RTL launch. Reproduction creates new attempts rather than overwriting receipts or logs.

Standalone softmax accepts only public score writes plus retained-max preparation; the real PS, LNexp and G entities handle all score reads/EXP writes/normalization reads/probability acknowledgments. The full head exposes only QKV32 production writes and one start; it has no score/prob injection port. The passive TB checks actual accepted/returned operands and production commits, all final values and native bank readback, not internal payload assignment. Normal full/sliding cases check all QK products/tree/scale, shifts/EXP/sum/div, AV products/key partials and context. Normal service cycle is measured after QKV readiness; all768 preparation writes are separately counted and must remain in any end-to-end accounting.

Finite grants are legal external stalls, so their longer observed cycle count is separated from the no-stall limits. Directed numeric cases change actual public score/max inputs only: NaN score, finite subtraction overflow, positive shifted EXP domain and true underflow-to-zero total. A combined early phase8/late phase7 case checks logical ordering against physical arrival. Invalid rows drain actual accepted work and never publish valid result reads. Error/abort DONE hold, response hold across DONE consumption and release wait on real debts. Reset checks require actual nonzero pending/inflight state and a fresh-generation complete reload and normal result where claimed; no forced zero, invented completion, or reset RAM clear is used.

This scope is a single logical RTL head. No physical fit, routed300MHz, board result, TANH, Decision true input, pre-RoPE path,16head or complete model is accepted from these runs. R003 HEAD16-06 is independently authorized and budgeted; it starts after this batch is frozen.
