# M007 Host / CPU handoff v1

The sole wire schema is `schema.json`. The Host codec is Python; C++ wire
constants and the SV package are generated by `PYTHONPATH=host python3 -m
m007_deploy.generate`. The package is a proposed versioned handoff for subsequent
hardware integration, and has no assigned XRT register offsets or BO group IDs.

The 512-byte little-endian control frame carries request_id u64, generation u32,
five full SHA256 identities, exact masks/16 marker slots, qtype and candidate
count, plus u64 address/span pairs. H0 is 128x1024 F32 = 524288 bytes. The output
payload is 17x1024 F32 = 69632 bytes, in marker slot order followed by raw CLS.
Control metadata is separate from both payloads. Duplicate slots/holes preserve
their order; inactive slots explicitly map to CLS. No candidate is truncated.

`validate_tail_ready` requires exactly the same request, identity, generation,
successful status and 17408 retired output elements before returning the data.
This validates a supplied real completion; it cannot prove an unconnected device
retired data. Address validation accepts the real BO allocation regions once the
device owner supplies them. There is no successful device stub.

`cpu_contract.py` imports the existing hash-pinned strict independent reference
math, preserving gamma LN, marker LN, baked scorer bias, explicit scorer bias,
GELU, F32 FC2, candidate mask/prob/stats, raw CLS, F16 ACT FC1 and Q8 ACT FC2.
The original whole-graph oracle stays independent and read-only. This backend
is a functional adapter and has no CPU timing acceptance claim. Its identity
profile uses numeric=reference-source SHA and layout=schema SHA; these are
explicit CPU contract tags, not final production device build tags.

Run from the E002 experiment root, under the common resource guard:

```
PYTHONPATH=host python3 -m m007_deploy device-status
# exit 3 and JSON status NOT_RUN; never runs CPU Attention
PYTHONPATH=host python3 -m m007_deploy prepare-h0 --token-ids ids.i32.bin --gguf MODEL --output H0.bin
PYTHONPATH=host python3 -m m007_deploy cpu-contract-tail --request request.bin --identity identity.json --tail tail.bin --gguf MODEL --output logits18.bin
```

The tail command explicitly accepts a CPU contract fixture. A future production
transport must call `validate_tail_ready` first and cannot substitute the CPU
gather helper when a device is unavailable.

`frontend.py` and `native_frontend.cpp` now provide real state/questions JSON
rendering with the original native BPE/questions/recipe source. The model has no
`ggmlc.decision`; this is explicitly its native Laya compatibility recipe, bound
to actual metadata and source SHA. It is not a claimed GGUF baked recipe.

The local assembler preserves the original template, renderer, tokenizer and mask
replacement order, but constructs the entire uncut sequence. <=128 tokens is
accepted and only then padded; >128 returns LENGTH_ERROR. It does not use the old
48-token option cap or head/state/total resize. An option longer than48 tokens is
retained when the entire sequence fits S128. Noul always has false/true candidates;
Choice/Score preserve input order and reject >16, without candidate or marker loss.

The business decoder binds the original `DecisionEngine::decode_answer` function
body as an explicit local source adaptation. Only the signature exposes its
recipe/ACT inputs; arithmetic and original temperature, confidence, tie, ACT and
rounded-answer semantics stay verbatim. Inputs and finite F32 intermediates are
checked before it, preventing the old softmax uniform fallback. Prepared JSON,
question, request/generation, model/reference/schema/build and file identities are
checked before decoding. Invalid values fail explicitly and produce no answer.

Build under the common guard with `tests/m007_deploy/build_frontend.py`, using the
known native-source identity evidence and a fresh AT build directory. The helper
links no ModelExecutor and cannot execute Attention. The test-only original-source
oracle loads real GGUF via the original GGUF library and calls original BPE,
build_sequence and a separately compiled original decode member body. It imports
no new assembler or decoder wrapper. This tests adaptation/identity semantics;
it is not a whole native engine or a new independent mathematical gold.

```
PYTHONPATH=host python3 -m m007_deploy frontend-prepare --input request.json --native NATIVE_BINARY --assets ASSET_EVIDENCE_JSON --gguf MODEL --output-dir PREPARED
PYTHONPATH=host python3 -m m007_deploy decode-answer --prepared PREPARED --question-index 0 --logits18 logits18.bin --native NATIVE_BINARY --assets ASSET_EVIDENCE_JSON --gguf MODEL --output answer.json
```

These reference-backend CLIs start a cold native/model verification session. BPE and business
decode are native; H0 and the entire 68KiB-to18-logit tail still execute the explicit
Python reference contract backend. Functional stage timers include the stated
loads/wrapping and are not CPU latency acceptance. A persistent native H0/tail
session is provided separately below. XRT sessions, final BEGIN transport,
real BO/platform binding, full forward and board remain NOT_RUN.

`native_session.NativeSession` is the persistent native CPU entry for R002.
It verifies/loads assets once and holds its native worker pool and weights until
close. Production prepare/finish executes no Python numerical reference and
launches no process. This build requires x86_64 AVX512F/BW/VNNI, CPU0–3 and the
recorded glibc2.39 libm. Each native caller temporarily pinsCPU0; workers pin1/2/3;
caller FE/MXCSR/affinity are restored on both success and error.

```python
from pathlib import Path
from m007_deploy.frontend import load_json_strict
from m007_deploy.native_session import NativeSession

with NativeSession(Path(LIBRARY), Path(MODEL), Path(ASSET_EVIDENCE)) as session:
    prepared = session.prepare(load_json_strict(Path("request.json")), request_id=1, generation=1)
    h0 = prepared[0].h0  # exact128x1024 F32, owned output
    # Caller supplies an independently produced69632B compact tail for this request.
    result = session.finish(prepared[0], tail_bytes)
    logits18, original_business_answer = result.logits18, result.answer
```

This is explicitly `native_cpu_contract`, deviceNOT_RUN. No CPU Attention is
called. The request wire uses logical CPU-contract addresses, not actual XRT BO
bindings. A real transport must supply actual BO identities/addresses and pass
real TAIL_READY metadata via `completion=`; no device completion is fabricated.
At most64 requests may be pending. Finish retires its prepared request; source,
question, id/generation, model/build and Session epoch must remain bound.

Default `cache_mode="full"` fills every50368 model-token post-initial-LN row once:
206307328B. It stores no request/tail/logit/answer memoization. Reload creates a
new cache and rejects old Prepared objects. `cache_mode="lazy"` is the same math
with true row misses, used for independent cache/cold diagnostics. Initialization
also completes the original tokenizer's static regex construction, discarding
the generic one-letter result. No request sequence is pre-tokenized or cached.
