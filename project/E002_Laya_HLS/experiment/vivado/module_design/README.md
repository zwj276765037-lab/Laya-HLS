本目录维护15个功能模块的source/、rtl/、tb/。当前build `04934c15b3f83e842ec2e92ac2a81bf2`完整CPU141点与真实13口HLS CSim47点通过，HLS RTL/IP及完整top Vivado OOC综合已完成，exit0、blackboxes0；映射资源345,505 LUT、287,466 FF、437 DSP、690 BRAM tiles、179 URAM。**新增RTL静态核查确认QK/AV合法context路径固定E_SHAPE，不能认定现有生成RTL可成功完成整网。** 当前[15模块接口/算力与条件性能报告](../project/source/performance_and_interfaces.md)汇总逻辑接口、真实端口、Q8成功图预算和新增异常；各模块design/results页首有对应入口，旧阶段记录按历史范围阅读。

```text
module_design/<模块>/
├── source/
│   ├── design.md       # 原规格位置/章节＋当前详细设计、接口、流水与验证安排
│   └── results.md      # 平台、资源、频率、性能/带宽与验证状态
├── rtl/                 # 预留维护的自定义/封装RTL；isolated HLS生成RTL留build目录
└── tb/                  # P0合同、P1/P2数值及关联链路TB
```

## 原文与当前设计怎样维护

- [design_source](../design_source/README.md)统一维护总体/模块约束。各模块`design.md`第2节列出原规格路径、对应章节及其作用，章节链接可直接定位原文。
- 每个`source/`只保留`design.md`和`results.md`：前者维护详细设计与差异，后者维护平台/资源/性能与证据。原规格更新时联动检查引用位置、当前设计和相关测试。
- 150MHz是实验综合请求；TM16/TN8、64路FP及双buffer等为后续生产配置。13端口的实际位宽、burst、资源与II以完整top报告为准，未测项目保持未测。
- 模块之间共用[15接口/流水](../design_source/15_integration_interfaces_and_pipeline.md)；Q8/FP/向量引擎、缓存和BO都按真实共享关系管理，不能按目录数重复计硬件。

## 代码与验证位置

`top`负责集成，`kernel_wrapper`负责平台边界，`forward_controller`负责调度。HLS→Vitis/xclbin→XRT路线保持；HLS源采用项目约定路径，自动生成RTL留构建目录；各模块rtl用于需要维护的自定义/封装硬件。

P2实际源由[config/full_sources.cmake](../../config/full_sources.cmake)登记，纯数值、完整存储/owner与typed任务分别维护在hls/operators、hls/common和hls/memory；完整调度/顶层按task合同接入。模型导出器与独立整图参考/反例位于tools和tests，模块TB通过统一构建调用，不复制第二份实现。

P0唯一源码与契约TB保留在各模块历史映射及[task.md §10](../../hardware_agent/task.md)；其`std::vector`/`std::map`主机合同不链接进P2综合。P1三模块共用数值源登记于[config/numeric_sources.cmake](../../config/numeric_sources.cmake)，提取共享行/窗口算术后仍执行P1回归。

阅读顺序：先看[top设计](top/source/design.md)与[top结果](top/source/results.md)，再读模块当前摘要与分阶段证据。实际验收分别报告CPU、CSim、代表性RTL、完整top实验综合、布局布线/时序、xo/xclbin和上板；实际性能按当前串行F0结构与报告复算，不能沿用早期生产阵列估算。
