The first failure is `Common 17-170` at `tb/create_project.tcl:27`: direct `set_property` parses the leading `-mode out_of_context` value as a command option. The previously successful `vivado/project/scripts/create_project.tcl:27` uses `set_property -dict [list {STEPS.SYNTH_DESIGN.ARGS.MORE OPTIONS} {-mode out_of_context}]`. The candidate adopts that exact form.

All seven original XCI files have `ip_inst.gen_directory` under the old `subcore_prj.gen`. Staging them in one flat `stage/ip` directory and registering them with `add_files` produced seven `IP_Flow 19-2162` shared-output locks and seven `Vivado 12-13650` warnings pointing outside the run. The installed Vivado 2025.2 manual at `Vivado/doc/eng/man/import_ip` says `import_ip -srcset sources_1 <files>` copies an XCI into the project-local source tree. The candidate imports each staged XCI separately, without `-quiet`, and checks all seven imported IP objects before any `generate_target` call.

The pre-generation gate requires each `IP_FILE`, `IP_OUTPUT_DIR`, imported XCI `gen_directory`, and the single runtime `OUTPUTDIR` value to resolve within the fresh project. It requires each output directory to be exactly `vivado/q8_same_source_ooc.gen/sources_1/ip/<name>`, each `IS_LOCKED` to be false, and each original/staged XCI to match the frozen input manifest byte-for-byte. It records imported XCI hashes and exact JSON differences; the only permitted paths are `/ip_inst/gen_directory`, `/checksum`, and `/ip_inst/parameters/runtime_parameters/OUTPUTDIR/0/value`. The original and imported `OUTPUTDIR` structures must each be one object containing exactly one nonempty string value; the imported value must resolve to the exact expected IP output directory. Every FP parameter, component reference, boundary, and other XCI field remains equal. A failed check stops before target generation and leaves the imported copy and `ip_import_preflight.json` for review.

Both Tcl entry points invoke the checker through `/usr/bin/env -u PYTHONHOME -u PYTHONPATH /usr/bin/python3`. This removes only Vivado's incompatible Python search environment; checker arguments and semantics are unchanged.

`verify_project.tcl` follows the imported file rather than expecting the stage XCI to be directly registered.
