# Compact Ws extraction implementation notes

This supplements the byte-frozen `design.md`; it does not change its proof or execution contract. The sealed prior report recovery ended at its 1,800 s guard limit. Its first Ws BRAM/pin inventory completed, but its full primitive pass did not. The actual result is bound by SHA256 `72e2c049186233e84a374c1e645bc0af21d6bcf2be56d00bf27b8fed5d67c843`; the independent timeout review is bound by SHA256 `3a1a351c418d774eb63a7ba223ba1ec7ef58b8576e709faf575ed4dffa000f75`.

`tb/extract_ws_graph.tcl` opens only the sealed DCP. It gets the full design's cell names in one batch, keeps only the eight exact Ws hierarchy roots and descendants, then queries properties and pins only for those selected cells. It emits all selected primitive properties, including exact LUT/BRAM initialization values, and all selected cell pins. A pin's net is reduced to a canonical hierarchical component using Vivado's documented `get_nets -segments`; aliases are cached. Each component is emitted once with its segments and driver pins/ports. Constant net reporting queries drivers, never all loads, so the prior repeated whole-chip constant fanout cannot recur. Selected incident pins are derived from the compact pin table. The 8-bank graph includes both physical BRAM ports, parity pins and local decode/read mux cells. The exact logical interface additionally includes `reset` and `clk`.

Revision v2 uses a pin object for both segment lookups, as in the installed `get_nets` manual. It caches each driver owner's primitive and blackbox classification, so hierarchy output aliases do not count as physical drivers. Missing/ambiguous owner flags, unknown primitive semantics and unverified zero-driver components become explicit extraction issues. The structural auditor independently checks driver kind, owner, output direction, constant reference and unique active driver. The v1 source and packet are preserved byte-for-byte under `source/preimages/v1/`; v2 packet checks are independent of output-directory existence after sealing, while a later execution gate must separately recheck fresh paths immediately before any run.

Every arbitrary Tcl string in a table is UTF-8 encoded and hex serialized, preserving tabs/newlines in property values. Stable IDs refer to cells (`cN`), pins (`pN`) and net components (`nN`). `issues.tsv` and `coverage.tsv` make incomplete extraction visible; the Tcl raises an error after closing tables if any coverage issue was recorded. The output marker says only `proof=REVIEW_REQUIRED`. `tb/audit_graph.py` checks table referential integrity and the exact boundary set offline; it never claims capacity, high-address or timing acceptance. Any external read selection cone is listed as unresolved, for a reviewed extension rather than an assumed connection.

The extractor also writes all-hierarchy utilization with `-hierarchical_min_primitive_count 0`, an auxiliary global DSP primitive list, and exact clock properties. These diagnostics do not replace the Ws graph. The existing OOC constraints are not changed. No new Vivado invocation or offline numerical proof is authorized by this source packet.

Known mapping hypothesis from the sealed first inventory, for review only: each bank has six x9/4096 BRAM blocks for data bits 0–8 (bit 8 on parity), three x4/8192 blocks for bits 9–12, two x2/16384 blocks for bits 13–14 and one x1/32768 block for bit 15. Logical write `address1` appears at physical A and read `address0` at B. This is a nominal storage layout, not proof of enabled writes or matching read selection. Address 20,991 and the 16,383/16,384 transition must be checked in the later exhaustive evaluator.
