## Same-source isolation and interface

`source/input_manifest.json` binds 230 generated Verilog files, 108 DAT, seven FP IP Tcl, the exact seven XCI, seven generated synthesis VHDL modules, six unique shared synthesis VHDL files, and the packaged OOC clock XDC: 366 records, each with byte count and SHA-256. `tb/verify_inputs.py --check` rehashes them read-only. `tb/make_source_packet.py --check` additionally binds this root's maintained scripts and documents, the accepted prerequisites/release, and the original input manifest before any future separately released execution. The `--stage FRESH_RUN_DIR` mode, if separately released, copies only project inputs into a fresh run under `stage/` and verifies the copies. The accepted generated tree and old full-kernel OOC project are never edited. Seven Tcl files are bound as IP generation provenance; this package uses the exact XCI copies as project IP inputs and compares actual generated synthesis products and compile order after project preparation.

The top is the existing nine AXI memory-bundle/two AXI-Lite Q8 kernel interface represented by the generated Verilog, with `ap_clk` as the OOC clock input. This package introduces no new data interface, reset rule, arithmetic, or memory behavior. The packaged constraint requests `ap_clk` at 6.667 ns (about 150 MHz). HLS's 1.8 ns uncertainty is a separate scheduling assumption and is not silently imposed as a Vivado XDC uncertainty. External clock source, shell, IO timing, HBM connectivity and platform reserve are outside standalone OOC evidence.

## Planned, separately gated project and synthesis phases

`tb/create_project.tcl` accepts a fresh staged run, creates only `q8_same_source_ooc` for `xcu55c-fsvh2892-2L-e`, adds the exact staged Verilog/DAT/XCI/XDC, configures top and OOC synthesis, binds the DAT pre-hook, and generates synthesis/simulation IP targets. It does not launch top synthesis. `tb/verify_project.tcl` reopens that project and checks the part/top, staged Verilog/DAT/IP Tcl/XCI counts, registered project inputs, seven unlocked IP objects, 6.667 ns clock text, generated synthesis/simulation VHDL presence, actual Vivado synthesis compile order and per-file libraries, and IP status. It records compile-order and IP reports. `tb/verify_project_outputs.py` then independently hashes all seven generated synthesis VHDL products against their original manifest records, records the six shared-VHDL candidates and their hashes, and marks any byte difference or missing shared file in actual compile order as review-required. The 243 candidate compile files are a source hypothesis, not a forced acceptance count.

`tb/prepare_dat.tcl` copies all 108 exact DAT files into the **actual synthesis process working directory** immediately before synthesis, compares every byte and emits a cwd/count marker. `tb/synth_ooc.tcl`, only after a later execution release, launches one top OOC synthesis run, requires that marker in the raw run log, preserves initialization/trim/warning lines and the full log, rejects black boxes, and writes a DCP plus full and hierarchical utilization, clocks, check_timing, unconstrained paths, and timing summary. It calls the independent `tb/report_ws_banks.tcl` physical inventory. A source-preparation success here cannot be mistaken for a completed synthesis.

## Ws physical mapping question

The source has eight independent logical Ws banks (`ws_U`, `ws_8_U`, …, `ws_14_U`), each 20,992 × 16 bits. LOAD writes bank address `4*b+j` over `scale_span/64` beats with `j=0..3`, and validation/compute reads `(n/8)*G+g` or `tile*G+g`. For the supported Wi K=1024,N=5248 shape, `T=656`, `G=32`, so `T*G=20,992` and the final legal address is 20,991. The DAT has 20,992 zero initialization words, but runtime writes make this mutable storage. A wrapper-only inference result multiplied by eight would not measure the actual top.

The logical banks require 335,872 bytes total. Sixty-four BRAM18 primitives hold only 147,456 bytes before width/depth/port effects, a 188,416-byte shortfall. The capacity-only aggregate floor is 146 BRAM18 equivalents; separately allocated banks require at least 152. Illustrative 1,024×18 BRAM18 or 2,048×18 BRAM36 geometries are not measured mappings. `report_ws_banks.tcl` inventories each retained bank hierarchy, physical RAM references/configuration, address/enable/write/data pins, connected nets and endpoints, and direct observed bit-14 logical address pins. Its full primitive inventory includes BRAM, URAM, LUTRAM, FF and LUT categories; address/control source pins receive fanout and endpoint/driver reports. It explicitly labels high-address connectivity as requiring netlist review. If a bank cannot be mapped to physical memory or the primitive inventory is unavailable, the script fails after writing raw inventories. A future reviewer must reconcile RAMB18/RAMB36/URAM/LUTRAM/FF storage, parity, cascade and duplication, inspect 0–20,991 read/write paths and especially 8191/8192, 16383/16384 and 20991. Numerical high-address exercise or equivalent proof remains a separate gate.

## Limits
