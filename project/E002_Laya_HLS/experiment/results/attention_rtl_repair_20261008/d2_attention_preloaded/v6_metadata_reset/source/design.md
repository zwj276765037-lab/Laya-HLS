## Implementation

`source/attention_preloaded_slice.cpp` is copied from the reviewed V5 top and changes only persistent metadata initialization before the original command path. `metadata_initialized` is one static false scalar under the HLS reset pragma. At the top of each accepted call, a false value invokes `reset_metadata(runtime,pending,ticket_counter)`; completion changes it to true. No ABI port or command value changes. Normal memory binding, observed clearing, report, cleanup, owner facade, production controller include, and the four real numeric task calls stay in their original order after this gate.

The initializer uses explicit scalar/member stores and fixed-bound loops. [The complete field checklist](metadata_field_checklist.md) names every persistent metadata field, exact cold default, and bound. The 15,360 owner u32 coverage words dominate the source store count. Other fixed loops cover 4,162 input mirror entries, 192 cache-metadata coverage words, 256 operation counters, 48 pending descriptor words, and short identity/descriptor arrays. The initialization is intentionally finite and unrolled resource costs/latency are unknown before HLS scheduling. Hardware reset clears only the scalar; all other persistent metadata is overwritten on the first post-reset accepted command. A reset during initialization must restart the initializer on a later command.

`FullCache` numeric payload arrays are never passed to the reset helpers. The CPU-only hook clears solely the scalar and is guarded out of synthesis. The 13-port local `FullMemory` object is constructed after initialization and still binds CPU observers only in the non-synthesis branch. No runtime-held `FullMemory` is introduced into synthesized persistent state. Production owner/numeric helpers and all standalone production translation units are unchanged.

## Verification source and boundaries

The copied V5 test retains its frozen three legal scenarios, 17 DUT negative markers, and one independent corrupt-image producer rejection. Three additional CPU source scenarios use the scalar-only test hook: (1) pending BEGIN/FILL then reset, old RUN `NO_PENDING`, preserved external QKV bytes, fresh BEGIN/RUN with ticket and QKV epochs exactly 1; (2) successful numerical RUN then reset, old RUN `NO_PENDING`, selected raw nonzero QKV/ATT_OUT payload retained, fresh numerical BEGIN/RUN; (3) failed/closed bad-ticket import then reset, old RUN `NO_PENDING`, fresh numerical BEGIN/RUN. All post-reset reports require zero tasks, claims, coverage, ticket, request/generation and published refs. CPU test code does not simulate the hardware reset pin.

The future RTL test must use the same elaborated instance. After a quiescent BEGIN/RUN boundary it will assert/deassert the actual reset pin, zero/read back all pointer CSR pairs, rebind the intended buffers, and send an old RUN before any new BEGIN. It must check exact `NO_PENDING` status/detail, zero tasks/claims/coverage/ticket, then a deliberately fresh BEGIN/RUN with numerical checks. After a real numerical RUN, passive inspection must select one actually written nonzero raw cell from each reachable KV, SCORE, and AV payload and selected external QKV/ATT_OUT bytes. The pin reset, first post-reset metadata sweep, and `NO_PENDING` report must retain those cells. This sampled dynamic check is supplemented by a static generated-RTL review of every numeric payload RAM reset/write cone; sampling alone is not an all-address proof. No internal force/deposit or waveform flood is permitted.

Generated-source review must establish that only `metadata_initialized` is reset, the first accepted command dominates every report/parse/owner/numeric state read, no reset/meminit sweep reaches numeric payload, and no new pointer escape appears. The existing cold `.dat` initialization is a separate power-up mechanism. The initial source pragma follows a Vitis-supported form used elsewhere in this workspace, but whether a namespace-static scalar is honored exactly as intended is **unverified** until synthesis and generated-RTL inspection.

The host must invalidate all pre-reset receipts and deliberately rebind a fresh request/generation. Since tickets and owner epochs restart at 1, this repair does not supply cross-reset anti-ABA identity when a host recreates a byte-identical request after reset; that requires a separate persistent identity or ABI design.
