# Externally loaded Attention results

New verification boundary defined; implementation, strict CPU preparation, and one standard-libm CSim run are complete. Independent review of the CSim evidence is pending. Production fe067 is unchanged. Target for later synthesis is xcu55c-fsvh2892-2L-e at requested 150 MHz, with automatic pipelining/array partition disabled as in the existing D2 configuration. These are target settings, not achieved timing. Resource, latency, bandwidth, place-and-route, timing and board measurements are unmeasured. Synthesis, multi-transaction RTL binding and numerical RTL remain gated and unexecuted.

The implementation uses the official B1/S64 Decision layer0 QKV intermediate and package build tag `fe067c8aa0627ad770096f9721394645`. Each source tensor is 786,432 bytes. Each QKV host BO is 12,582,912 bytes; the later RTL modeled prefix is 10,240,064 bytes including 64 tail sentinel bytes. The host checker verifies 25,165,824 physical bytes per image, including holes and full tails. These dimensions are fixed design inputs, not measured throughput.

Strict CPU validation used GCC 13.3.0, C++17 `-O2 -fno-fast-math -ffp-contract=off`, four CPUs, nice 19, idle I/O, an 8 GiB owned-process RSS cap, a 120-second timeout, 0.2-second samples and a 192 GiB MemAvailable floor. The independent Python/NumPy fixture generation and CPU build/execution each ran in their own guarded process. Three legal BEGIN/RUN cases passed: base head0/query0, base head15/query63, and changed-QKV head0/query0. Seventeen negatives passed: second BEGIN while pending, replay RUN, missing plane, missing row in the nonselected shard, stale ticket, wrong request/generation/bank/epoch/source hash/image hash, wrong version/shape/build tag/reserved field/word count, and a physically corrupted image blocked by the independent checker before RUN. Missing coverage returned the production QKV E_BUFFER detail; partial ATT_OUT full publish returned the production ATT_OUT E_BUFFER detail. The three legal cases each retired four real tasks and checked exact QK, nonlinear-tolerance probability, exact AV from actual probability, separate end-to-end AV tolerance, owner states, all QKV bytes/hashes and full ATT_OUT sentinels. The numerical pass is a CPU result only.

Final guarded fixture generation is in `runs/fixture_guard_v2`; its first BEGIN and RUN descriptors are frozen as two 640-byte U32 little-endian files. Final guarded CPU build and execution are in `runs/cpu_build_guard_v5` and `runs/cpu_execute_guard_v5`. The build linked 24 official production translation units plus the wrapper that includes the unchanged controller; it exited 0 in 7.87 s with 162,444 KiB peak owned RSS. The CPU execution exited 0 in 7.56 s with 66,736 KiB peak owned RSS. Both guards reported no trigger and more than 447 million KiB minimum host MemAvailable. Earlier passing CPU runs are retained. The first freeze audit in `runs/cpu_freeze_guard` failed because two executed negative checks lacked individual log lines; the v5 test prints all 17 and the corrected audit passed in `runs/cpu_freeze_guard_v2`. These are process-tree peaks, not a hardware memory bound.

The final test rechecked all 25,165,824 host QKV bytes after BEGIN and both before and after each RUN, compared actual prefix/full-host SHA256 digests to an independently generated manifest, and scanned the whole 8 MiB ATT_OUT for sentinels outside the selected 256-byte row/head output. The base first-call descriptor bytes matched the separately generated frozen BEGIN/RUN pages. Across successful BEGIN calls, each 64-bit ticket and both QKV epochs advanced exactly once. The final log records six real owner claims in each legal case and the actual per-shard prefix digests. The intentionally corrupt input had a correctly serialized, falsely complete receipt, but the physical checker rejected it before RUN; no arbitrary-payload hardware authentication is claimed.
