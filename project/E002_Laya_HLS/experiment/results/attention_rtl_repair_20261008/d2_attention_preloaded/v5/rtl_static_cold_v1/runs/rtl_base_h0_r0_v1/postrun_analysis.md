## Static explanation to test in a reviewed diagnostic source

The frozen testbench requires `b_selected_index==64` and the final B address `att_out_base+252` (`tb/att_cold_control.svh:278-279`), and later requires 64 ATT_OUT AW/W/B and 256 bus bytes (`tb/att_cold_control.svh:204-213`). The production AV loop writes 64 F32 values (`hls/operators/full_tasks_attention.cpp:367-375`). Each `task::write` calls `full_write(...,4)` (`hls/operators/full_task_common.h:94-104`), whose body writes four individual bytes (`hls/common/laya_full_memory.cpp:149-165`). The generated `attention_preloaded_slice_full_write.v:1325` issues a user write request of length one for each byte. The ATT_OUT m_axi instance has an 8-bit user port and 32-bit bus (`attention_preloaded_slice.v:11997-12009`); its preprocessor makes each length-one user request a zero-based one-byte request (`attention_preloaded_slice_att_out_m_axi.v:1079-1102`). The sequential burst converter aligns its start address to a four-byte boundary (`:2987`) and maps such a request to one bus beat (`:2989`, `:3030-3044`); bus `AWSIZE` is two (`:2121`).

That source path predicts **256 one-beat AW/W/B transactions**, **1,024 bus write bytes** and **256 useful strobed bytes** for 64 F32 outputs. Four byte requests for the last F32 map to the same final bus AW address, `att_out_base+252`. The frozen `b_selected_index==64` and later 64 AW/W/B / 256 bus-byte expectations therefore appear to encode 64 values as 64 bus writes. This is a source-derived hypothesis; the failed runtime did not print final port-5 counts or the selected B index. The final address and all response-retirement checks must remain enforced.
