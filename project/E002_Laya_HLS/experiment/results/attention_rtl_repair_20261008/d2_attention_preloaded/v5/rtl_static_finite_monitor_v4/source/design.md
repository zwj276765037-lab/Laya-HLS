# Head15 v4 bounded record-boundary diagnostic source design

The v3 actual runtime ended at the first top reset predicate at 6666 ps, before any command. Fourteen owner reset messages print zero records and zero counts; no wrapper or successful top witness ran before termination. Top raw fields and individual predicate results were not printed. Root cause is unresolved. This design authorizes source preparation only and preserves all v3 evidence.

## Full-testbench instrumentation candidate

Before any record reset predicate can issue a fatal at the first settled negative edge, obtain a complete central bounded diagnostic snapshot for all seven ports. Use explicit constant-index emitted statements for every port so diagnostic collection itself cannot hide a variable-index expression issue. The generator may produce these statements from a fixed seven-entry port-name map.

For each port print owner .accepted_r_record and .r_count at both monitor instances, wrapper dut_monitor_accepted_r_record and ram_monitor_accepted_r_record, wrapper output ram_accepted_r_record and ram_r_count, and constant-index top array record/count. Also print the same top element reached through the existing variable p loop. Print records and counts in hexadecimal and binary as raw four-state values; include port index, simulation time, clock/reset values and seen-reset-posedge flag. This limited hierarchical read is diagnostic only, never a numerical authority or a replacement for the explicit record interface; no old internal r_accept scalar may be used. Bind every hierarchical name to the actual frozen named-instance map.

For each top record/count pair print independently: record case-nonzero, count case-nonzero, per-field reduction-X detection ((^field) === 1'bx), per-field $isunknown, original $isunknown on the variable-index concatenation, original expression at a literal constant index, and $isunknown on a local151-bit packed snapshot assigned from the same fields. Print the packed snapshot raw bits too. Evaluate and print diagnostics before the preserved original predicate. Do not merge its logical terms into a replacement authority. Keep X/Z checks strict. At later first-R witnesses, retain existing exact ordinal/address/beat/RID/last checks; diagnostic output remains bounded to reset and first-R per port per reset.

Diagnostics must finish before any sibling record reset diagnostic fatal, independent of active-region block ordering. A practical candidate is a centralized top diagnostic task called immediately before the unchanged top predicate, together with wrapper reset-fatal diagnostics routed through the same top coordinator or deferred only within the diagnostic-check execution until a `diagnostic_snapshot_complete` flag for that exact negative edge is set. Do not delay clock/reset, transaction processing or state update. The owner posedge reset assertion already passed in v3; retain its behavior. If coordination would alter a predicate or cause a scheduling dependency, prefer a single top task that reads all three boundaries and directly invokes all preserved wrapper and top record-reset checks in their original same-negedge observation phase; record this exact assertion-placement-only change. Do not modify numerical/transaction check timing. Provide a source-level explanation and literal diff for independent review; no claim that this instrumentation alone fixes the fault.
