# Finite execution proposal — not released

No command in this plan has been executed for this module. A later signed gate must name the exact source packet, resource limits, run directory and command sequence before any qtype1 generation, CPU build, CSim, HLS or RTL run.

1. Reverify [source_packet.json](../source/source_packet.json) and its complete production closure. Under a separate materialization release, run `python3 tb/materialize_qtype1.py FRESH_QTYPE1_DIR` once into an absent directory. Bind the new request, row-reference and 65536-word gold hashes to the run; keep the exact frozen qtype2 fixture unchanged. The script checks the complete packaged EMBEDDING BO, the original GGUF type tensor bytes, native `ir_1410` capture and original-R0 independent reference source.
2. Under a separate CPU release, build one test binary in a fresh run directory from the 25 `syn.file` entries in [config_type_producer_binary.cfg](../source/config_type_producer_binary.cfg), plus [test_type_producer_binary_slice.cpp](test_type_producer_binary_slice.cpp), with the previously accepted `/usr/bin/g++ -std=c++17 -O2 -fno-fast-math -ffp-contract=off` flags, the four `syn.cflags` include paths, and `-lm`. Record exact argv, compiler version, source hashes, exit status and full log. A candidate per-command guard is 4 GiB owned RSS and 120 s; review this against current host capacity and actual build profile before signing it.
3. Run the binary twice as **separate new processes**, with arguments `PACKAGE FIXTURE FRESH_QTYPE1_DIR qtype2` and `PACKAGE FIXTURE FRESH_QTYPE1_DIR qtype1`. Each run has a fresh static runtime. The TB asserts the exact five-task/three-claim original owner sequence, all 65536 F32 output words, all selected TYPE_ROWS words, both unused type rows, and all mapped-state sentinels. Preserve first failure and do not weaken expected values. CSim, if separately released, needs the same cold case split; the TB also accepts `LAYA_D2_TYPE_PACKAGE`, `LAYA_D2_TYPE_FIXTURE`, `LAYA_D2_TYPE_QTYPE1_DIR` and `LAYA_D2_TYPE_CASE` when the CSim tool cannot pass `argv`.
4. Only after CPU and source review, run the candidate HLS config in its own immutable output directory under an explicit tool/time/RSS gate. Inspect actual generated port names, source closure, physical schedule, operator invocations and address ranges. Then construct a new seven-port RTL TB with [static_mapping.json](static_mapping.json), the accepted AXI endpoint/debt monitor conventions, qtype-specific selected-row reads, 206 sparse pages, first sampled `ap_done` checks and real R/B terminal stalls. Derive a **new finite cycle limit** from measured/scheduled ingress, one EMB_TYPE and four 16×1024 ADD_TYPE tasks; the unary Mode3 limit is unrelated.

The proposed CPU resource guard is a planning value, not a measured result or authorization. RTL wall-time, memory and cycle ceilings remain deliberately unset until actual generated source and schedule are reviewed. No OOC or board step follows from this plan without its own release.
