# Mode3 runtime plusarg entry candidate — source only

The first frozen alias-v2 runtime stopped at simulation time 0 ps with `D2_MODE3_LIMIT_ARGUMENTS`; XSim returned 0, then the independent checker failed because no raw state/observed pages existed. The [first-failure evidence](../runtime_first_failure_evidence_v1.json) and four mutable snapshot artifacts are preserved. This analysis did not run XSim, compilation, CPU gold, or any EDA tool.

The runner's guarded argv carried `131072` and `140000` correctly. Its XSim call supplied `-testplusarg "+MODE3_DUT_LIMIT=131072"` and `-testplusarg "+MODE3_TOTAL_LIMIT=140000"`. Both literal leading `+` characters appear in the archived `xsim_script.tcl` **and** the child `xsimkernel.log` argv. The testbench calls `$value$plusargs("MODE3_DUT_LIMIT=%d",dut_limit)` and `$value$plusargs("MODE3_TOTAL_LIMIT=%d",total_limit)`; spelling, underscores, decimal format, declaration order, and the positive inequality (`140000 >= 131072`) match the intended values. The combined `||` expression can skip the second call if the first fails, so this failure alone does not identify which argument was rejected.

Installed Vivado 2025.2 `doc/eng/man/xsim` describes `-testplusarg <args>` for `$test$plusargs` and `$value$plusargs`, saying such arguments are visually distinguished by `+`. That wording does not specify whether the shell value itself should contain a literal `+` when passed through XSim's launcher. A successful same-version Q8 static runner in this workspace passes `-testplusarg "MODE=$mode" -testplusarg "CASE_COUNT=$cases"` **without** literal `+`. Its testbench uses the same two-call `!$value$plusargs(...) || !$value$plusargs(...)` pattern, and its XSim log reaches `Q8_ACT_STATIC_LEGAL_PASS commands=9`. A separate successful clock-wait diagnostic likewise passes `-testplusarg WAIT_MODE=V` and reaches `CLOCK_WAIT_MODE_PASS`. This comparison weighs against a generic two-call/short-circuit defect and supports an extra-prefix channel mismatch. It does not prove the simulator's internal normalization without a newly authorized run.

The [candidate diff](run_mode3_plusarg_only.diff) deletes exactly those two literal `+` characters in a copied runner. It leaves the two numeric values, testbench, clocking `#1step`, same-edge `#1ps` debt, AW/W ordinal 127, terminal holds, DUT, generated snapshot, fixture and gold untouched. The candidate itself is not executed. A future reviewer-approved overlay must bind the copied runner and a fresh runtime directory in a new source packet while reusing the exact accepted 328-file snapshot and 14 prepared pages. The frozen alias-v2 packet and failed runtime directory must remain unchanged. No unchanged retry or current-gate runtime authorization follows from this candidate.
